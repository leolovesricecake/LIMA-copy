## 1. 研究问题与论述边界

论文需要回答四个递进问题：

1. Sparse deletion-Möbius 是否是有效且有竞争力的 LLM 归因方法？
2. 方法的收益是否来自显式建模并使用 signed interactions？
3. 不强制 hierarchy 是否保留了有价值的非层级交互？
4. deletion-Möbius 表示是否更紧凑，或更容易由有限查询恢复？

论文可以论述：

> 在指定的删除算子和 value function 下，LLM 的局部 masked function 存在可由有限差分验证的非加性行为。
> 直接恢复低阶稀疏 deletion-Möbius 超图，可以在不强制父项存在的情况下建模并利用这些行为。

论文不能直接论述：

- 学到的超边等同于模型内部神经机制；
- deletion-Möbius 中缺少父项能够反驳 Fourier hierarchy；
- 一次实验中的较小 support 自动证明某个坐标更可压缩；
- 未使用共享 held-out masks 的 R² 可以进行严格逐方法比较。

## 2. 已确定的协议

### 2.1 Target

- 默认 `target_mode=predicted`。
- 各方法根据相同模型、prompt、verbalizer 和完整输入预测规则独立计算 target。
- 继续在样本结果中保存 `predicted_label` 和 `target_label`。
- 不建立 shared target manifest，不增加跨实验 target-label 检查，也不让汇总脚本依赖该检查。

### 2.2 三类 mask

| mask 类型 | 用途 | 是否跨方法共享 |
|---|---|---|
| Attribution training masks | 查询原模型并训练归因方法 | 不共享；属于方法机制 |
| Ranking evaluation masks | 按各方法排名删除或保留词 | 不共享具体 mask |
| Surrogate held-out masks | 测试 surrogate 对未查询 coalition 的预测 | 共享 |

Training masks 保持方法原生：

- Sparse Möbius 使用自己的 sampler，主配置与代码默认值为 `uniform_size`；
- ProxySPEX 使用原生 ProxySPEX sampler；
- 两者只统一 attribution budget，不共享训练 observations。

Ranking evaluation 只统一：

- 删除比例或固定 top-k；
- chunk/evaluation 粒度；
- mask operator；
- value function 和 target mode；
- faithfulness 定义。

### 2.3 严格 surrogate held-out

采用严格二阶段方案，不使用各方法独立生成的 held-out masks。

第一阶段，每个方法保存：

- 样本 ID、chunks 和 active-player 映射；
- 训练 keep masks；
- 对应的原模型 label scores 和 attribution values；
- 可重建 surrogate 的系数、support 和拟合配置。

第二阶段，审计脚本针对一组待比较 runs：

1. 按 dataset、model、sample 和 active chunks 对齐结果；
2. 合并该样本所有方法的训练 mask，得到训练 mask 并集；
3. 默认从固定 seed 的 Bernoulli-0.5 分布中过采样候选；near-full 作为可选敏感性分布；
4. 删除训练 mask 并集中的候选；
5. 为所有方法选择完全相同的剩余 masks；
6. 仅查询一次原模型并保存全类别 label scores；
7. 分别用各方法 surrogate 预测并计算 R²、NRMSE 和 MAE。

约束：

- mask 文件统一保存为 keep-mask 语义；
- held-out masks 不得参与 support selection、refit 或超参数选择；
- held-out 与交互验证查询不计入 attribution budget；
- 若有限 coalition 空间不足，则使用全部共同未见 masks；低于最小测试数的样本单独标记，不静默丢弃；
- 第一版建议每种分布 64 个 masks，pilot 后根据置信区间决定是否增至 128。

### 2.4 查询量

分别记录：

- attribution logical budget；
- attribution unique masks；
- attribution physical model calls；
- ranking evaluation calls；
- surrogate audit calls；
- interaction verification calls；
- cache hits。

论文中的方法查询效率以 attribution logical/unique queries 为主。物理调用数必须注明 cache 状态，审计与评估调用不能混入 attribution cost。

## 3. E1：总体归因有效性

### 问题

Sparse deletion-Möbius 是否在不同任务和模型上优于或匹敌现有归因方法？

### 对照

- Sparse deletion-Möbius；
- ProxySPEX；
- Inseq 中选定的一阶归因基线；
- AML 仅在能够统一数据、target 和评估协议时纳入。

### 控制变量

- 相同 dataset、split、模型和样本集合；
- `target_mode=predicted`；
- 相同 value function、word chunking 和 word evaluation；
- 相同 attribution budget；
- 相同 faithfulness evaluator。

### 指标

- AOPC、AUPC；
- AOPC comprehensiveness、AOPC sufficiency；
- 主删除比例下的 comprehensiveness、sufficiency；
- attribution logical/unique queries；
- 模型 forward calls 和失败率。

主结果表报告 canonical budget；预算曲线归入 E5。所有结果报告样本级均值、标准差、配对置信区间和效应量。

## 4. E2：交互是否必要

### 三个版本

| 版本 | 拟合模型 | 节点投影 |
|---|---|---|
| A：additive | degree 1 | singleton |
| B：interaction-fit-only | degree 2 | singleton-only |
| C：full interaction | degree 2 | signed equal share |

A 和 B 是不同 surrogate；B 和 C 共用同一个 degree-2 surrogate，只改变从超边到节点分数的投影。

### 为什么比较指标不同

- **A vs B** 改变函数类，主指标是共享 held-out 上的 R²、NRMSE、MAE。它回答：“加入二阶项是否更好地拟合 masked function？”
- **B vs C** 不改变 surrogate，因此两者的 held-out 预测和重构指标完全相同。主指标必须是 ranking faithfulness。它回答：“已学到的交互是否应进入词排名？”
- **A vs C** 同时比较 held-out 重构和 faithfulness，表示完整交互方法相对纯加性方法的总收益。

实现中三种版本仍统一保存全部 surrogate 和 faithfulness 指标；上面的划分只规定各假设检验的主指标，避免事后选择有利指标。

## 5. E3：交互是否对应可验证的非加性

只验证估计绝对值最大的二阶 deletion-Möbius 边。对词对 `{i,j}`：

```text
m^-_ij =
f(N \ {i,j}) - f(N \ {i}) - f(N \ {j}) + f(N)
```

四个值精确给出所选删除坐标下的二阶 deletion-Möbius coefficient。该结果表示局部删除干预下的非加性，不表示内部神经机制。

每条 selected edge 保存：

- `estimated_coefficient`；
- `exact_coefficient`；
- `absolute_error` 和 `squared_error`；
- 四个 keep masks、四组 label scores 和四个 attribution values。

每个 selected edge 匹配一个随机词对，并控制词间距离。

汇总：

- MAE、RMSE、Pearson 和 Spearman；
- selected 与 matched-random 的精确系数绝对值；
- 配对 bootstrap 置信区间和配对检验；
- 多 seed selection frequency 和符号稳定性。

## 6. E4：Hierarchy

### 配置语义

实现并区分：

- `hierarchy=none`：不对选择 support 施加父项约束；
- `hierarchy=strict`：最终选择 support 满足强层级，即任一二阶项存在时两个 singleton 父项都存在；
- 现有“先筛 singleton、再生成 interaction candidates”的实现改名为 `hierarchy=parent_screening`，不再称为 strict。

第一版 strict 采用可复现的 support-pruning 协议：

1. 在完整低阶候选上执行与 `none` 相同的 sparse selector；
2. 根据 selector coefficient 和统一 tolerance 定义选择 support；
3. 删除任一父 singleton 不在选择 support 中的二阶项；
4. 在剩余严格层级 support 上使用相同 refit；
5. 分开保存 selection support、strict support 和 refit coefficients。

该协议保证最终结构满足 strong hierarchy，并最大程度保持 selector、masks 和超参数一致。它是“对同一初始支持施加严格层级剪枝”的消融，不应表述成全局最优 hierarchical regression。

### 比较

保持 basis、training masks、budget、selector、refit 和 projector 相同，比较：

- faithfulness；
- shared held-out metrics；
- top-edge 精确验证；
- 运行时间；
- `total_support_size`；
- `singleton_support_size`；
- `pair_support_size`。

第一版不做 matched-support hierarchy。因此：

- 可以说明施加 strict pruning 后的整体变化；
- 可以分析被删 orphan edges 是否可验证且是否影响 faithfulness；
- 如果两种方法 support size 差异较大，不能单独据此断言 hierarchy 本身导致性能变化。

对 `none` 选出的边再按 2、1、0 个 singleton 父项存在分组，统计 exact coefficient、
频率、稳定性以及移除该组边后的 faithfulness 变化。

## 7. E5：可压缩性与恢复效率（先不做）

E5 只有在共享 held-out protocol 完成后执行。

### 7.1 坐标可压缩性

在完全相同的 Sparse training masks、solver 和 degree 下比较：

- direct deletion-Möbius；
- direct Fourier。

对 `k = 1, 2, 4, 8, ...`：

1. 按选择系数绝对值保留 top-k terms；
2. 只在 training observations 上 refit；
3. 在共享 held-out masks 上计算 R²、NRMSE 和 MAE。

报告：

- R²-log(k) 曲线；
- `k@R²=0.80/0.90/0.95`；
- 各阶 support 数量。

这组实验回答坐标可压缩性，不使用单次 Lasso 非零项数代替。

### 7.2 完整方法紧凑性

比较 Sparse Möbius 与原生 ProxySPEX。两者共享 held-out masks，并分别保存完整解释表示：

- Sparse 的 selection/refit Möbius support；
- ProxySPEX 的 unrefined Fourier、refined Fourier 和最终 interaction support。

分别展示：

- explanation support size 与 faithfulness；
- retained top-k explanation terms 与 faithfulness；
- surrogate held-out 结果。

ProxySPEX 的 tree proxy、refined Fourier 和最终低阶 interaction 不是同一个对象，结果中必须分别命名，不能把 tree proxy 的 R² 当成最终解释表示的 R²。

### 7.3 有限查询恢复

使用：

```text
budget in {64, 128, 256, 512}
```

每个 budget 记录：

- Bernoulli held-out R²、NRMSE、MAE；可选报告 near-full 敏感性结果；
- faithfulness。

报告 quality-budget 曲线、budget-quality AUC，以及达到预设质量阈值所需的最小 budget。

## 8. E6：消融与敏感性

## 9. 代码与结果产出改造

### 9.1 Sparse estimator

修改 `mobius/methods/sparse/estimator.py`：

- 显式保存 candidate、selection、strict 和 refit support；
- 保存各阶 support 数；
- 支持 Lasso raw、Ridge refit 和可选 OLS；
- 支持在指定 support 上重新 refit；
- 保存 regularization path 和 CV validation error；
- 提供稳定的任意 mask 预测接口。

修改 `mobius/methods/sparse/hierarchy.py`：

- 将当前 `strong` 重命名为 `parent_screening`；
- 实现上述 `strict` support pruning；
- 输出被 hierarchy 删除的边及其父项状态。

### 9.2 方法 observation artifacts

Sparse 与 ProxySPEX 都新增独立 sidecar artifact，不把大型 observations 塞入 `metrics.json`：

```text
surrogates/<sample-id>.json
observations/<sample-id>.npz
```

至少保存训练 masks、values、active-player 映射、support 和预测所需参数。ProxySPEX 运行时直接保存：
- 最终 Fourier support；
- 最终 Fourier 系数；
- 预测任意 mask 所需的信息。

### 9.3 新增脚本

- `scripts/build_surrogate_holdout.py`：加载多个 runs，自动识别并记录输入目录、模型和数据集，然后生成并查询共享 held-out masks；
- `scripts/evaluate_surrogates.py`：在共享 held-out 数据上评估各 surrogate；
- `scripts/verify_interactions.py`：二阶边验证和 matched-random 对照；
- `scripts/analyze_hierarchy.py`：父项分组、移除实验和 support 统计；
- `scripts/analyze_compressibility.py`：top-k refit 与 R²-support 曲线；
- `scripts/collect_paper_results.py`：生成论文长表；

现有 `scripts/collect_results.py` 继续作为紧凑 run 汇总，不承担上述样本级论文分析。

### 9.4 结果协议

核心 schema 保持稳定，新增审计产出：

```text
<run>/
├── samples/
├── observations/
├── surrogates/
└── analyses/
    ├── heldout.jsonl
    ├── interaction_verification.jsonl
    ├── hierarchy.jsonl
    └── compression.jsonl
```

run-level aggregate 保存到 `analyses/paper_metrics.json`。所有分析文件都记录输入 run ID、配置摘要、样本覆盖数、失败数和额外查询成本。
